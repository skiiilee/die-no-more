# 2단계 · 정보 구조 및 화면 구성안

> 상태: **승인됨 (2026-11-12, [ADR-0003](../decisions/ADR-0003-implementation-decisions.md) D1)** — 4단계 구현 기준.  
> 대상: Die No More — 개인 사용자 1명, 한국어 중심, 실내 식물 우선.  
> 근거: 병합된 `docs/08-functional-review.md`, `docs/reviews/claude/2026-11-09-stage1-feasibility.md`, `docs/01-requirements.md`.  
> 2단계는 **화면 설계 및 기능서 제작**까지만 수행한다. 3단계 검토·수정이나 4단계 구현은 하지 않는다.

## 1. 설계 원칙

1. **건강 점검(F05)이 핵심 기능:** 홈과 내 식물 상세에서 바로 시작할 수 있도록 동선을 짧게 유지한다. 정확하지 않은 AI 결과는 '확정 진단'으로 표현하지 않는다.
2. **사용자는 한 명:** 다중 사용자, 초대 및 식물 공유 화면을 만들지 않는다. 개인 기록은 비공개다. 단일 사용자라고 로그인/보호 필요 여부가 자동 해결되는 것은 아니다.
3. **식물 추가의 동등한 시작 경로:** 식물 추가 화면(S03)을 처음 열면 **이름 검색창과 사진 스캔 버튼이 동시에 보이고 바로 사용 가능**해야 한다. 사진 스캔이 선행 조건이 아니며, 식별 오류·API 초과·사진 없음에도 이름 입력 또는 '종 미상'으로 화분을 등록할 수 있다.
4. **관리 정보는 필요할 때:** 첫 종 등록 시 DB에 자료가 없을 수 있다. 관리 정보가 없으면 사용자가 `직접 입력하기` 버튼을 눌러 빈 입력 양식을 작성한다. 이 버튼은 AI를 호출하지 않는다. 입력한 내용은 사용자 검토 후 저장하며, 같은 종이면 기존 자료를 재사용한다.
5. **화분과 종을 분리:** 몬스테라 2개를 기르면 공통 관리 지침은 재사용, 사진·관찰·할 일·관리 이력은 각각 관리한다.
6. **실내 식물 우선:** 야외 식물도 사용자 사진의 검증 대상이 될 수 있으나 초기 화면·용어는 실내 관리에 최적화한다. 미지원 종은 수동 등록과 일반 기록 기능 제공.
7. **모바일 우선, 데스크톱 대응:** 복잡한 화면 전환보다 현재 식물과 다음 행동에 집중. UI 언어는 한국어.
8. **단계 분리:** 현재 산출물은 정적 설계 문서다. 배포(Next.js + Vercel, ADR-0002)·DB 스키마·API 키 연결 등 구현 선택은 이 문서가 승인하지 않는다.

## 2. 제안 내비게이션 (검토 전)

- 모바일 하단 주요 탐색: **오늘 / 내 식물 / 건강 점검 / 더보기** (4개).
- '오늘': 예정된 할 일과 관리 현황, 새 식물 등록 바로가기.
- '내 식물': 내 화분 목록, 검색, 화분별 상세 및 관리 이력.
- '건강 점검': 등록된 화분을 고르거나 사진으로 바로 점검.
- '더보기': 전체 관리 기록/알림 설정/개인정보 및 외부 분석 사용 안내.
- 하위 화면(촬영, 식별, 등록, 건강 점검 결과, 관리 기록 입력)은 필요한 동작만 제공하고 이전 화면으로 돌아갈 수 있게 설계한다.

```text
진입 / 개인 사용자 확인(S01)
└─ 오늘(S02) ─────────┬─ 새 식물 등록 → 식물 추가(S03) ─┬─ 이름 검색 ────┐
                     │                                  └─ 사진 스캔 → 촬영/갤러리 선택 모달
                     │                                                  → S03-P 사진 목록 → [사진으로 식물 찾기] ─┤
                     │                                     S04-A 검색/스캔 결과 목록
                     │                                       → 식물 요약 보기
                     │                                       → [이 식물 추가하기] → 등록(S05)
                     ├─ 관리할 일(S09) → 활동 기록(S08)
                     └─ 건강 점검(S07)
내 식물(S11) ─────────┬─ 화분 상세(S06) ──┬─ 건강 점검(S07)
                     │                    ├─ 기록하기(S08)
                     │                    └─ 사진·관찰 이력(S10)
                     └─ 새 식물 등록(S03/S05)
건강 점검(S07) ──────┬─ 등록 화분 선택 또는 사진만으로 진행
                     └─ 결과 / 추가 확인 / 기록 저장 여부 선택
더보기(S12) ─────────┬─ 개인 설정 및 외부 사진 전송 안내
                     └─ 기록/데이터 관리
```

## 3. 화면 목록과 기능 매핑

| 화면 | 이름 | 주요 정보 / 가능한 행동 | 연결 기능 |
|---|---|---|---|
| S01 | 개인 진입 | 개인 사용자 접근, 비로그인/세션 만료 안내 | F01 |
| S02 | 오늘 | 관리할 일, 최근 관찰, 건강 점검/식물 등록 시작 | F05, F06, F11, F13 |
| S03 | 식물 추가 시작 | 이름 검색창과 '식물 스캔' 버튼 동시 노출. [식물 스캔] 클릭 시 **촬영/갤러리 선택 모달**을 먼저 표시하고 선택한 사진은 S03-P에서 확인. 이름 검색은 S04-A 후보로 진행 | F02–F04 |
| S03-P | 업로드한 사진 목록 | 업로드 사진 1~5장 목록·미리보기, 개별 삭제, [사진 추가] → 촬영/갤러리 선택 모달, Pl@ntNet 외부 전송 동의 체크박스(미동의 시 분석 불가), [사진으로 식물 찾기] → S04-A (ADR-0003 D5) | F02–F04 |
| S04-A/B | 식물 검색 결과·정보 확인 | **S04-A:** 후보별 참고 사진(있으면)·한국어 이름·학명·보기. **S04-B:** 선택 종의 실제 확인된 기본 정보 요약을 표시하고 사용자가 '이 식물 추가하기'를 누르면 S05로 이동 | F03–F04 |
| S05 | 화분 등록 | **별명(선택; 미입력 시 식물 이름 표시)**·종(확정/수동/미상 가능)·위치·사진 및 **화분별 초기 관리 상태**(마지막 물 준 시기, 채광 정도, 마지막 분갈이 시기, 화분 재질, 물·비료 알림 설정) 입력·저장 | F06, F08–F09, F13 |
| S06 | 화분 상세 | 현재 상태, 개별 이력, 종별 관리 정보, 핵심 액션 | F05, F07, F10–F12 |
| S07 | 건강 점검 | 사진, 관찰 증상, 가능한 원인/불확실성/추가 확인/재점검 | **F05** |
| S08 | 관리 기록 | 활동을 먼저 고르지 않고 **물주기/비료/분갈이/가지치기/흙 상태/관찰을 한 화면에서 각각 선택 입력**하여 한 번에 저장. 입력하지 않은 항목은 기록하지 않음 | F08–F09 |
| S09 | 관리할 일 | 개별 상태 변경 외에 **다중 선택 후 일괄 완료/미루기/건너뛰기**. PC 체크박스 상시 표시, 모바일 [상태 한 번에 바꾸기]로 선택 모드 진입 | F11, F13 |
| S10 | 사진·관찰 이력 | 사진·관찰/관리 활동의 시간순 열람 | F12 |
| S11 | 내 식물 | 화분 카드, 검색, 상태 필터, 정렬, 신규 등록 | F07 |
| S12 | 더보기/설정 | 개인 설정, 외부 사진 전송 안내, 데이터 관리 | F01 |
| S13 | 관리 정보 직접 입력 | 종별 정보 유무, '직접 입력하기', 빈 입력 양식, 저장·검토 완료 | F10 |

S13은 F10의 독립 작업을 위한 **별도 화면**으로 확정했다(ADR-0003 D13). 기존 S01–S12의 식별자는 보존한다.

## 4. 주요 사용 흐름

### A. 식물 신규 등록 — 이름 검색 또는 사진 스캔

1. '새 식물 등록' → **S03 '식물 추가' 첫 화면에 이름 검색창과 '식물 스캔' 버튼을 함께 표시**한다. 별도 사진 촬영 화면을 먼저 통과할 필요가 없다.
2. **검색 경로:** 한국어 이름·학명·품종명으로 입력해 가능한 결과를 조회한다. 데이터가 없으면 '검색 결과 없음'을 알리고 이름 직접 입력/종 미상 등록 경로를 제공한다. 초기 종별 관리 DB는 비어 있으므로 **인기 식물 목록을 미리 채우지 않는다**. 검색 데이터는 Perenual·Trefle을 사용한다. 인기·추천 목록은 MVP에서 보여주지 않는다(ADR-0003 D11).
3. **스캔 경로:** S03 [식물 스캔] → **촬영/갤러리 선택 모달**에서 [카메라로 촬영] 또는 [갤러리에서 선택] → **S03-P**에 업로드한 사진 1~5장 목록·미리보기 표시. S03-P에서 개별 삭제 또는 [사진 추가]로 선택 모달 재진입 → [사진으로 식물 찾기]를 눌러 Pl@ntNet 식별 → **S04-A 후보 목록**. S03-P에는 Pl@ntNet 외부 전송 동의 체크박스가 있으며, 체크하기 전에는 [사진으로 식물 찾기]를 실행할 수 없다(ADR-0003 D5). 스캔을 취소하거나 실패해도 S03의 이름 검색은 사용 가능하다.
4. 두 경로 모두 S04에서 후보를 누르면 **식물 간단 정보 확인 화면**을 먼저 보여준다. 이름(한국어/학명), 사진(있는 경우), 출처가 확인된 관리 난이도·빛 조건 등 **실제 확보한 기본 정보만** 표시한다. 정보가 없는 항목은 숨기거나 '정보 없음'으로 안내하며 AI로 내용을 자동 생성하지 않는다.
5. 사용자는 정보를 본 뒤 **'이 식물 추가하기'**를 누를 때만 S05 화분 등록으로 진행한다. '다른 식물 찾기'를 누르면 검색 결과 또는 S03으로 돌아간다. S04 선택 자체가 화분을 저장하지는 않으며, 확실하지 않으면 이름 직접 입력 또는 '종을 모르겠어요'가 가능하다.
6. **화분 별명은 선택**이며 비우면 식물 이름(한국어 이름, 없으면 학명)을 표시한다. 실내 위치와 함께 **마지막 물 준 시기, 현재 채광 정도, 마지막 분갈이 시기, 화분 재질**을 S05에서 선택하도록 한다. **물 알림·비료 알림 사용 여부는 해당 유형의 API 관리 데이터가 확인된 경우에만 표시**한다. 날짜 달력 대신 사용자가 지정한 **기간 범주**를 보여주며, **식별 실패나 종별 관리 정보 없음은 저장을 막지 않는다**.
7. 종 정보가 확정되고 자료가 없으면 S13에서 '직접 입력하기'를 눌러 관리 정보를 직접 기록할 수 있다.
8. 마지막 물주기·분갈이 응답은 **정확한 날짜가 아닌 사용자가 선택한 경과 기간 범주**로 화분별 초기 상태에 보관한다. 임의 날짜로 변환하거나 실제 작업 이력을 자동 생성하지 않는다. 채광 정도와 화분 재질은 해당 화분의 환경/용기 정보이며, 물·비료 알림은 그 화분의 알림 사용 선택이다. 기존 같은 종의 관리 기준은 재사용하되 화분별 기록은 독립적으로 시작한다.

**S05 초기 관리 선택지 (사용자 지정):**

| 항목 | 선택지 |
|---|---|
| 마지막 물 준 시기 | 당일 ~ 1일 전 / 일주일 전 / 한달 전 / 모름 |
| 빛이 들어오는 정도 | 직사광선 / 밝은 간접광 / 보통 / 약함 / 잘 모르겠음 |
| 마지막 분갈이 시기 | 당일~1일 전 / 2~6일 전 / 1주 이상~1개월 미만 / 1개월 이상~2개월 미만 / 2개월 이상~3개월 미만 / 3개월 이상~6개월 미만 / 6개월 이상~1년 미만 / 1년 이상 / 모름 / 한 적 없음 (경계는 [05 검토본](05-pc-mo-wireframe-snapshot.md) 규칙 1) |
| 화분의 재질 | 플라스틱 / 테라코다,도기 / 유리 / 자기,석기 세라믹 / 화단 |
| 알림 설정 | 해당 유형의 API 관리 데이터가 있으면 물 알림 / 비료 알림 각각 켜기·끄기 노출. 해당 데이터가 없으면 그 유형은 숨기고 둘 다 없으면 설정 영역 미노출 ([05 검토본](05-pc-mo-wireframe-snapshot.md) 규칙 2, ADR-0003 D16). API 필드 검증 전에는 기능 플래그로 모두 숨김 |

기간 범주는 입력 당시의 시점과 함께 기록해야 의미가 유지된다. **분갈이 기간은 [05 검토본](05-pc-mo-wireframe-snapshot.md) 규칙 1의 서로 겹치지 않는 10개 구간으로 확정**되었다. **알림 노출은 규칙 2, 일정 산출은 ADR-0003 D16**을 따른다. API 데이터 검증 전에는 알림 항목을 숨기고 임의 주기를 만들지 않는다.

### B. 핵심 사용 흐름 — 사진 기반 건강 점검 (F05)

1. 홈/화분 상세/하단 '건강 점검' → 등록된 화분 선택 또는 미등록 사진으로 시작.
2. 사진을 선택하고 잎·줄기·흙 상태, 이상을 발견한 시점 등 알고 있는 사항만 작성. 모르면 건너뛸 수 있다.
3. 외부 분석 서비스로 사진을 보내기 전 **전송 대상과 개인정보 안내를 확인하고 동의**.
4. '분석하기' → 진행·대기 화면 → 결과에 **관찰된 증상 / 가능한 원인 / 먼저 확인할 사항 / 주의할 행동 / 분석 불확실성** 표시.
5. 근거가 부족하면 단정 대신 '판단 어려움'과 추가 사진·관찰 요청. API 실패·한도 초과 시 사진 재선택·기록만 하기 경로 제공.
6. 등록된 화분이면 결과를 해당 화분 기록에 저장할 수 있다. 미등록 사진은 저장할 화분 선택 또는 등록을 안내하며 자동 생성하지 않는다.

### C. 관리 기록/할 일

1. '오늘' 또는 화분 상세의 관리 기록에서 S08로 이동하면 별도 행동 선택 화면 없이 **모든 관리·관찰 입력을 한 화면에 제공**한다. 실제 작성한 항목만 이력을 생성한다.
2. '흙 확인'이면 흙 상태(마름/적당/젖음/모름) 기록 후 완료; **실제 물주기로 기록되지 않는다**.
3. '물 주기'는 사용자가 실제 급수 행위를 확인한 경우에만 기록. 중복 저장 방지.
4. S09 PC는 행별 체크박스를 항상 표시하고, 모바일은 상단 [상태 한 번에 바꾸기]로 선택 모드에 진입하여 복수 선택 후 완료/미루기/건너뛰기를 일괄 적용한다. 실제 물주기 완료는 수행 여부를 별도 확인하며 미루기/건너뛰기로 작업 이력을 생성하지 않는다.
5. 개별 또는 일괄 변경 후 해당 할 일 상태를 반영하고 일부 변경 실패는 구분해 표시한다.

### D. 종별 관리 정보 직접 입력

1. 사용자가 종을 확정한 화분을 연다.
2. 종별 관리 정보가 있으면 읽고 수정할 수 있다.
3. 자료가 없다면 '관리 정보 없음'과 **'직접 입력하기'** 버튼을 표시한다.
4. 사용자가 버튼을 누르면 빛·물·온도·흙·주의사항 등을 적을 수 있는 **빈 입력 양식**이 열린다. 이 버튼은 외부 AI를 호출하지 않는다.
5. 입력값을 저장하고 사용자가 검토 완료 여부를 결정한다. 저장한 정보는 같은 종의 다른 화분에 재사용한다. 입력하지 않고도 화분 관리 기록을 계속 사용할 수 있다.


## 5. 모바일·데스크톱 설계 규칙 (구현 아님)

- 모바일 기준 폭: 약 360–390px 화면에서 한 번에 하나의 주요 동작을 제시한다. **S05 화분 등록은 기본 정보와 초기 환경이 이어진 단일 스크롤 양식**이다. 작은 화면에서도 핵심 버튼과 상태 문구가 겹치지 않아야 한다.
- 데스크톱 기준: 중앙 내용 폭 제한, 홈/화분 상세에서 필요 시 2열 구성, 메뉴와 현재 맥락이 동시에 보이게 한다.
- 주요 버튼의 동사는 '분석하기', '식물 등록', '직접 입력하기', '기록 저장'처럼 실제 행동을 명시한다.
- 의미 있는 상태는 색만으로 구분하지 않는다. 날짜, 상태(미검증, 대기, 완료 등)를 한국어로 표시한다.
- 빈 화면·권한 거부·느린 분석·오프라인·API 실패·할당량 초과·종 미상을 각 흐름에서 확인 가능하게 설계한다.
- 건강 점검에는 사진을 보고 확정 판단한 듯한 표현, 위험 조치 권유, 과도한 불안 유발 표현을 피한다.
