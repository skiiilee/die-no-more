## 기능별 사용 API

| 기능 | 명세 | 사용 API | 용도 |
|---|---|---|---|
| 식물 이름 검색 | F02, S03 | Perenual, Trefle | 이름으로 종 후보 조회 |
| 사진으로 종 식별 | F02–F04, S03 | Pl@ntNet | 사진으로 학명 후보 조회 |
| 사진 기반 건강 점검 | F05, S07 | Pl@ntNet (질병 식별, `POST /v2/diseases/identify`) | 사진에서 질병 후보 조회. 확정 진단으로 표시하지 않음 |
| 종 관리 정보 조회 | F10, S04, S06 | Perenual | 물, 빛, 독성, 병해충 관리 가이드 표시 |
| 종 영문 일반명 조회 | F10, S04 | Perenual | 번역 입력값으로만 사용. 화면에 직접 표시하지 않음 |
| 한국어 이름 표시 | F02–F04, S04, S06 | Google Cloud Translation (식물DB에 번역어가 없을 때만 호출) | 식물DB의 한국어 이름을 표시하고, 식물DB 검색에 씀. 없으면 번역해 식물DB에 저장. 학명 매칭에는 쓰지 않음. 검색 재시도 시 한국어 입력을 영문으로 바꾸는 데도 씀 |

## 데이터 연결 기준

- 후보는 **학명**을 기준으로 합치고 중복을 없앱니다. 별도 API는 쓰지 않고 앱 내부에서 처리합니다.
- 관리 정보는 학명으로 Perenual을 조회합니다. 값이 없으면 "정보 없음"으로 표시합니다. 값을 새로 만들지 않습니다.
- 관리 정보 값은 Perenual 응답을 사용하고, 항목마다 출처(Perenual)와 조회 날짜를 기록합니다.
- 이름 검색 순서: ① 식물DB에서 찾기(한국어 이름, 영문명, 학명) → ② 없으면 입력 그대로 Perenual·Trefle 조회 → ③ 결과가 없고 입력이 한국어면 영문으로 번역해 Perenual·Trefle 재조회 → ④ 그래도 없으면 직접 입력. 사용자는 한 번만 입력하며, 이 순서는 코드가 자동으로 실행한다.
- 식물DB와 사용자 화분DB는 분리합니다. 식물DB에는 학명 기준의 종 정보, 영문 일반명, 한국어 이름, 출처 API, 조회 날짜를 저장합니다. 화분DB에는 사용자가 등록한 화분과 기록을 저장합니다.
- 식물 검색 결과는 식물DB에 저장합니다. 키는 학명입니다.
- 한국어 이름은 식물DB에 저장된 값을 씁니다. 식물DB에 번역어가 없으면 Google Cloud Translation으로 번역해 식물DB에 저장한 뒤 표시합니다. 같은 학명은 한 번만 번역합니다. 번역이 실패하면 학명을 표시합니다.
- 학명과 관리 정보 값은 번역하지 않습니다. 번역은 화면 표시용 이름에만 씁니다.
- 화분을 표시할 때 이름은 별명 → 한국어 이름 → 학명 순으로 씁니다. 그 밖의 화면에서는 한국어 이름 → 학명 순으로 씁니다.
- 사용자가 확정한 종은 화분의 확정 종 정보로 저장합니다. 식별 API가 돌려준 후보 목록은 원본 그대로 별도로 저장하며, 두 값을 같은 필드에 덮어쓰지 않습니다. 후보마다 출처 API와 조회 날짜를 함께 기록합니다.

## 호출 위치

- Perenual, Trefle, Pl@ntNet은 모두 서버에서 호출합니다. API 키는 서버 환경변수에만 둡니다(`docs/03-architecture.md`).
- Google Cloud Translation도 서버에서 호출합니다. 번역 키는 서버 환경변수에만 둡니다.
