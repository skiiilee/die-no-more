## 추가: 실기기 버그 — [사진 삭제]가 회색으로 눌리지 않음
- 증상(사용자 실사용 테스트, PR #20 병합 후): S06에서 [사진 삭제] 버튼이 회색(비활성)이고 눌리지 않음.
- 원인 추정: [사진 추가]·[사진 삭제] 액션이 성공하면 같은 페이지(`/plants/{id}`)로 `redirect()` 했고, 이때 패널이 다시 마운트되지 않아 `useActionState`의 진행 중 상태가 남아 두 버튼이 계속 비활성으로 보임. 로그인한 실기기 재현 환경이 없어 브라우저에서 직접 재현하지는 못함.
- 수정: 두 액션은 `refresh()`(next/cache)로 S06을 제자리에서 다시 그리고 `{ status: "done" }`을 돌려줌. 패널은 마지막으로 시도한 동작(추가/삭제)의 메시지만 보여 줌. S05 등록은 다른 페이지로 가므로 그대로 `redirect()`.
- 테스트: 사진 추가 성공 뒤 두 버튼이 다시 눌리는지, 추가 실패 메시지가 삭제 시도 후 사라지는지(jsdom이라 Next 라우터 동작 자체는 재현하지 않음). `04-api-design.md`에 이유 기록.
- 다음: 배포 미리보기에서 휴대폰으로 사진 추가 → 바로 삭제가 되는지 확인.

## 추가: 실기기 버그 2 — 검색 후 [뒤로] 오면 [사진 삭제] 비활성
- 증상(PR #21 미리보기): 업로드 직후 삭제는 되지만, 검색 화면에 갔다가 [뒤로] 돌아오면 [사진 삭제]가 회색.
- 관찰: Cache Components에서 Next는 떠난 페이지를 숨긴 `<Activity>`로 남겨 두고 [뒤로] 때 다시 보여 줌(상태 유지). 버튼 비활성은 `useActionState`의 pending 값에서 왔고, 이 값이 되살아난 화면에서 풀리지 않은 것으로 추정.
- 수정: `PotPhotoPanel`이 액션을 직접 await 하고 자체 busy 상태(시작 시 설정, `finally`에서 해제)를 씀. 요청 자체가 실패(throw)하면 안내 문구를 보이고 버튼을 풂.
- 테스트: Activity 숨김→표시 뒤 버튼 활성, 요청 실패 시 문구와 버튼 활성. 단, Activity 테스트는 이전 코드에서도 통과함(jsdom에 Next 라우터가 없어 실제 버그는 재현 못 함). 요청 실패 테스트는 이전 코드에서 실패함. `npm run check` 387개 통과.
- 다음: 미리보기에서 사진 추가·삭제 → 검색 → [뒤로] → 버튼 확인.
