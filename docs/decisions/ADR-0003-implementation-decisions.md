# ADR-0003: 구현 착수를 위한 미결정 사항 일괄 확정

Status: Accepted (사용자가 Claude에게 결정 위임, 2026-11-12)
Date: 2026-11-12
Related: ADR-0001, ADR-0002, `docs/stage2/*`, `docs/08-functional-review.md` §6

## Context
2단계(화면·기능서)가 끝났고 사용자는 4단계(구현)로 넘어가기로 했다. 문서에 "미확정·추후 검토·결정 대기"로 남은 항목이 구현을 막고 있어, 사용자가 Claude에게 빠르게 검토해 채택하도록 위임했다. 이 ADR은 그 결정을 한 곳에 모은다. 다른 문서와 충돌하면 **사용자 확정 규칙(`05-pc-mo-wireframe-snapshot.md`) > 이 ADR > 그 밖의 문서** 순으로 따른다.

## Decision

### D1. 2단계 산출물 승인
`docs/stage2/01~05`는 4단계 구현 기준으로 승인된 상태로 본다. 같은 내용이 서로 다르면 위 우선순위를 따른다. `docs/06-ui-ux.md`의 화면 목록은 `docs/stage2/01-information-architecture.md`로 대체된다.

### D2. 접근 방식 (F01, S01)
- Supabase Auth 이메일 + 비밀번호. 소유자 계정 1개를 Supabase 콘솔에서 만든다. **공개 가입은 끈다.** 가입 화면은 만들지 않는다.
- S01 이외의 모든 화면과 API는 세션이 필요하다. 세션이 만료되면 S01로 보내고 로그인 후 원래 화면으로 돌아간다.
- 단일 사용자여도 모든 사용자 데이터 테이블에 `user_id`와 RLS를 둔다.

### D3. LLM 설명 기능
MVP에서 **채택하지 않는다.** 추천(F10)은 결정적 규칙과 출처 표시만 쓴다. 다시 도입하려면 새 ADR이 필요하다.

### D4. 사진 형식·용량 (F02, F05)
- 1회 1~5장. 허용 형식: JPEG, PNG, WebP. HEIC는 브라우저가 JPEG로 바꿔 주는 경우만 받고, 그렇지 않으면 "JPEG로 다시 선택해 주세요"를 안내한다.
- 원본 1장당 최대 15MB. 브라우저에서 긴 변 1600px로 줄여 JPEG(품질 0.85)로 다시 인코딩한 뒤 올린다.
- 서버는 파일 시그니처와 크기(처리 후 3MB 이하)를 다시 검사하고, 다시 인코딩해 **EXIF(위치 포함) 메타데이터를 제거**한다. 서버 처리 결과를 기준으로 한다.

### D5. 외부 사진 전송 안내 (S03-P, S07, S12)
- 별도 동의 화면·체크박스는 두지 않는다(S03-P는 사용자 확정, S07도 같은 방식).
- 전송 버튼 바로 위에 한 줄 안내: "사진은 식물 분석을 위해 Pl@ntNet으로 전송됩니다." 버튼을 누르는 것이 전송 선택이다. 누르지 않으면 외부 요청을 하지 않는다.
- S12에 보내는 대상(Pl@ntNet), 보내는 내용(사진, 선택한 기관 유형), 앱의 저장 범위를 안내한다. Pl@ntNet 외 제공자에는 사진을 보내지 않는다.

### D6. 사진·결과 저장 범위
- 업로드 사진은 비공개 Storage의 임시 경로에 둔다. 화분 등록·기록·건강 점검 저장에 연결되지 않은 사진은 **24시간 뒤** 하루 1회 정리 작업(Vercel Cron)이 지운다.
- 제공자 원본 응답은 저장하지 않는다. 정규화한 결과와 제공자 이름, 엔드포인트, 호출 시각만 저장한다. 식별 후보 목록은 정규화한 형태 그대로(순서·점수 포함) 별도 저장한다.

### D7. 외부 호출 방식 (03-architecture "Open decisions")
- 큐 없이 Route Handler에서 동기 호출한다. 제공자 호출 타임아웃 15초, 타임아웃·5xx에 한해 1회 재시도. 함수 최대 실행 시간 30초.
- 식별·건강 점검 요청은 `processing / completed / failed` 상태를 기록해 실패해도 입력과 사진을 잃지 않는다.

### D8. 무료 한도 관리
- 제공자별 하루 호출 수를 `api_usage_logs`로 KST 날짜 기준 집계한다. 한도 값은 서버 환경변수로 둔다. 도달하면 해당 기능만 멈추고 확정 문구를 보여준다.
- 유료 결제 자동 전환을 켜지 않는다. 실제 한도 값은 구현 첫 작업에서 각 제공자 공식 문서로 확인하고 확인 날짜와 URL을 `04-api-design.md`에 기록한다.

### D9. 오프라인
서비스 워커로 앱 셸만 캐시한다. 오프라인이면 상단 배너를 보여주고 저장 동작은 막되 **작성 중 입력은 화면에 유지**한다. 오프라인 기록 큐와 자동 동기화는 MVP 범위 밖이다.

### D10. 이름 검색 매칭과 같은 종 판정
- 식물DB 검색: 입력값의 앞뒤 공백 제거와 연속 공백 정리 후, 한국어 이름·영문 일반명·학명에 대해 대소문자 무시 부분 일치(`pg_trgm` 인덱스).
- 학명 정규화 키: 소문자, 앞뒤 공백 제거, 연속 공백 1개, 명명자 표기 없는 학명(제공자가 주는 without-author 값 사용). 후보 병합과 같은 종 판정은 **이 키의 완전 일치만** 쓴다. 별칭·오탈자·유사 이름은 자동으로 합치지 않는다.

### D11. 인기·추천 목록
MVP에서 보여주지 않는다. S03 첫 화면은 검색창과 [식물 스캔]만 보여준다.

### D12. 직접 입력한 이름과 종 미상
`user_plants.species_id`는 비워 두고, 사용자가 입력한 이름을 `user_entered_name`에 그대로 저장한다. 자동으로 학명에 연결하지 않는다. 나중에 S06 수정에서 검색 흐름을 거쳐 종을 연결할 수 있다.

### D13. 관리 정보 직접 입력 (S13, 08 §6-1)
- S13은 별도 화면으로 확정한다.
- 입력값은 해당 종의 관리 정보에 `source = user`로 항목별 저장한다. API 값은 덮어쓰지 않고, 화면에는 "직접 입력" 표시와 입력일·수정일을 함께 보여준다.
- "검토 완료"는 별도 상태 버튼이 아니라, 저장 전 미리보기에서 사용자가 [저장]을 누르는 것으로 본다. 화면 표기는 "직접 입력(사용자 확인)"이며 "검증됨"이라고 쓰지 않는다.
- **직접 입력한 값으로는 알림을 만들지 않는다.** 알림은 API 관리 데이터만 따른다(05 검토본 규칙 2).

### D14. 지원 식물 범위 (08 §6-3)
모든 식물을 등록할 수 있다. 화면 용어는 실내 식물 기준이다. 관리 정보가 API에 없으면 "이 식물의 관리 정보가 없습니다"와 [직접 입력하기]를 보여준다. 미지원 종에 대한 별도 차단은 없다.

### D15. 탐색
모바일 하단 4개 탭(오늘/내 식물/건강 점검/더보기)을 확정한다. PC는 같은 4개 항목을 왼쪽 세로 메뉴로 보여준다.

### D16. 물·비료 알림과 할 일 일정 (F11, F13)
05 검토본 규칙 2를 구현하는 계산 방식이다. 모든 간격은 API 데이터에서만 나온다.
- **물 알림:** Perenual 종 정보에 일 단위 급수 기준 범위(예: `5-7 days`)가 있을 때만 S05에 노출한다. 할 일 이름은 "흙 상태 확인"이다(실제 물주기 지시가 아님).
  - 기준일: 가장 최근 실제 물주기 기록. 없으면 등록 시점과 S05의 마지막 물 준 시기 범주.
  - 범주별 경과 일수 하한: 당일~1일 전 = 0, 일주일 전 = 7, 한달 전 = 30, 모름 = 기준 없음.
  - 첫 할 일 날짜: 등록일 + max(0, 범위 하한 − 경과 일수 하한). "모름"이면 등록일.
  - 실제 물주기 기록 후: 기록일 + 범위 하한.
  - 흙 상태 확인만 완료(물 안 줌): 완료일 + max(1, 범위 상한 − 범위 하한)일.
  - 건너뛰기: 원래 예정일 + 범위 하한. 미루기: 05 검토본 규칙 3.
- **비료 알림:** API가 일 단위 비료 주기를 제공할 때만 노출한다. 제공하지 않으면(현재 Perenual 기준으로 대부분 그럴 것으로 예상) 비료 알림 항목을 숨긴다.
- 날짜 계산의 시간대는 Asia/Seoul로 고정한다.

### D17. 알림 채널
MVP는 사이트 내 알림만(F13). S02에 오늘·기한 지난 할 일 수를 배지로 보여준다. 웹 푸시(F14)는 MVP 이후다.

### D18. 영구 삭제 처리
S12-D·S06-A의 영구 삭제는 하나의 서버 동작에서 DB 행과 Storage 사진을 함께 지운다. Storage 삭제가 실패하면 실패 목록을 보여 주고 다시 시도할 수 있게 한다(DB는 이미 삭제된 상태로 둔다).

### D19. 문서 정리 에이전트 주기
매주 월요일 08:40 KST(2026-11-11에 만든 예약 작업). ADR-0002 5항의 "frequency to be set"을 대체한다.

## Consequences
- `docs/stage2/*`, `02-mvp-specification.md`, `03-architecture.md`, `04-api-design.md`, `05-database-design.md`, `06-ui-ux.md`, `08-functional-review.md`의 미결정 문구를 이 ADR을 가리키도록 같은 PR에서 고친다.
- 구현 첫 작업은 제공자 약관·한도·응답 필드(특히 Perenual 급수 기준 필드와 무료 요금제의 종 상세 조회 범위) 확인이다. 확인 결과가 D8·D16의 가정과 다르면 새 ADR로 고친다.
- F05 출시 판정 기준(03 §4)은 그대로 유지한다.

## Alternatives considered
- 매직 링크 로그인: 메일 전달 지연과 다른 기기 로그인 불편 때문에 채택하지 않음.
- 작업 큐(Supabase Queue, Inngest 등): 제공자 응답이 수 초 수준이고 사용자가 1명이라 MVP에는 과함.
- 오프라인 기록 큐: 충돌 처리 비용이 커서 MVP 이후로 미룸.
